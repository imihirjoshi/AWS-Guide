AWS Mainframe Modernization

Migration and Transfer  ·  Advanced, most people never need it

Tools to move old mainframe programs to AWS, either running them as they are or rewriting them into Java.

Picture it as

An old factory machine that still works. You either build a new shed around it so it keeps running, or you rebuild it from scratch in modern parts.

What it actually does

Offers two paths, replatform with Rocket Software so COBOL and JCL keep running mostly unchanged, or refactor with AWS Blu Age which converts the code to Java or .NET. The managed runtime is closed to new customers, and the self managed experience moves to maintenance status on 30 July 2026, closing to new customers. AWS now steers new mainframe work to AWS Transform. Very few organisations ever need this.

Reach for it when

  • You already use it and are continuing an existing programme
  • You are studying the replatform versus refactor choice

Do not reach for it when

  • You are starting a mainframe migration now, look at AWS Transform first, this one is closing to new customers
  • You have an old server but not a mainframe, this is for IBM z/OS, use Application Migration Service

One small example

An insurer converts decades of COBOL batch jobs into Java Spring Boot services that produce the same output, checked line by line against the old system.

How you pay

Charged per compute hour for the runtime plus storage. Real cost is the multi year project and the testing, not the AWS line item.
