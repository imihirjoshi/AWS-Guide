AWS IoT Greengrass

Internet of Things  ·  Advanced, most people never need it

It runs AWS style code on your own hardware, near the machines, even without internet.

Picture it as

A branch office that can keep serving customers when the phone line to head office goes down, then sends the paperwork up later.

What it actually does

You install the Greengrass runtime on a Linux device such as an industrial PC or gateway. It runs components, which can be Lambda functions, containers or plain programs, caches messages while offline, talks to nearby devices, and syncs with IoT Core when the link returns. Version 1 is being retired, so use version 2. You are responsible for the hardware, the operating system and keeping it patched.

Reach for it when

  • Unreliable or expensive connectivity at the site
  • Decisions that must happen in milliseconds, locally
  • Data too bulky or too sensitive to send raw to the cloud

Do not reach for it when

  • Devices with a solid always on connection, plain IoT Core is far less work
  • Tiny microcontrollers that cannot run Linux, use FreeRTOS or ExpressLink
  • A single site where an ordinary local server and your own code would do

One small example

A gateway on a factory floor that reads a conveyor sensor, stops the line locally on a fault, and uploads a summary each hour.

How you pay

Per active device per month, plus the IoT Core messages it sends. The hidden cost is the field engineering to install and maintain hundreds of edge boxes.
