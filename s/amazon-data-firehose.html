Amazon Data Firehose

Analytics  ·  Learn this early

Takes a constant trickle of records and drops them into storage for you, in batches.

Picture it as

A funnel with a bucket under it. Drips go in continuously, and every so often the full bucket is carried off to the store room.

What it actually does

Formerly called Kinesis Data Firehose. You send it records and it buffers them for a set time or size, then writes them to S3, Redshift, OpenSearch or a partner like Splunk. It can compress, convert JSON to Parquet, and call a Lambda to tweak each record. It is fully managed with no shards to size, but it is one way and near real time, not instant, there is always a buffer delay of at least a minute or so.

Reach for it when

  • Shipping application or clickstream logs into S3 without writing a loader
  • Feeding a dashboard index in OpenSearch
  • Converting streaming JSON into Parquet for cheap querying

Do not reach for it when

  • If several different apps must read the same stream, or you need replay, use Kinesis Data Streams
  • If you need results in well under a second, the buffer makes this the wrong tool
  • For moving whole database tables, use AWS DMS or Glue, not a stream

One small example

A mobile app sends every screen view, and an hour later those events are sitting in S3 as tidy Parquet files.

How you pay

Per GB ingested, rounded up per record to 5 KB. Lots of tiny records cost far more than the raw byte count suggests, and format conversion is billed on top.
