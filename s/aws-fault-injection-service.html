AWS Fault Injection Service

Developer Tools  ·  Advanced, most people never need it

Deliberately breaks parts of your system so you can see how it copes.

Picture it as

A fire drill. You set off the alarm on purpose, on a day you choose, to find out whether people know the way out.

What it actually does

Formerly called AWS Fault Injection Simulator. It runs controlled experiments such as stopping EC2 instances, adding network latency, throttling an API, or failing over a database. You define stop conditions using CloudWatch alarms so the experiment aborts if real damage starts. This is a niche tool, useful mainly to teams that already have good monitoring and a real availability target.

Reach for it when

  • You claim multi AZ resilience and want proof
  • You are preparing for a game day or a disaster recovery test
  • You want to check that alarms and failover actually fire

Do not reach for it when

  • You have no monitoring yet, you will break things and learn nothing, fix observability first
  • You want to test application logic under load, use a load testing tool

One small example

Stopping every instance in one availability zone for ten minutes to confirm the load balancer keeps serving traffic.

How you pay

Per action minute during an experiment. The real cost is the outage you cause if you skip stop conditions, so never start in production without them.
