AWS IoT Core

Internet of Things  ·  Common, learn when you need it

It is the front door where your gadgets connect to AWS and send messages.

Picture it as

A post office for machines. Every device has its own registered address, drops off letters, and picks up letters left for it, even if it was switched off for a while.

What it actually does

Devices connect over MQTT, WebSockets or HTTPS using certificates, and publish messages to named topics. A rules engine then forwards those messages to other AWS services like Lambda, S3 or a database. It also keeps a 'device shadow', a stored copy of each device's last known and wanted state, so your app can read or set values while the device is offline. It handles the plumbing, not your application logic, and you still have to design topics, certificates and data format yourself.

Reach for it when

  • Many small devices sending small readings
  • You need per device identity and certificates
  • You want device data to land in AWS services automatically

Do not reach for it when

  • A handful of devices you control, where a plain HTTPS API behind API Gateway is simpler and cheaper
  • Phone or browser apps, use API Gateway or AppSync instead of pretending they are IoT devices
  • High volume telemetry that only needs to be streamed and stored, Kinesis Data Streams is a better fit

One small example

Two thousand water meters each publish a reading every fifteen minutes, and a rule writes each reading into DynamoDB.

How you pay

Per million messages, plus separate charges for connection minutes, rules engine actions and device shadow reads and writes. The surprise is that one incoming message can be billed several times over as it passes through each part.
