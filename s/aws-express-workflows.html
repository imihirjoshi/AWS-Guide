AWS Express Workflows

Application Integration  ·  Advanced, most people never need it

A fast, cheap mode of AWS Step Functions for very high volume, short jobs.

Picture it as

A quick checkout lane at the shop. It moves a lot of people fast, but it is not a different shop.

What it actually does

This is not a separate AWS service. Express Workflows are one of the two workflow types inside AWS Step Functions. When you create a state machine you pick Standard or Express, and you cannot change it later. Express runs for up to five minutes, has no limit on state transition rate, and is priced by the number of runs, how long they take, and the memory used. Standard runs up to one year and is priced per state transition. Express does not keep an execution history of its own, so you must turn on Amazon CloudWatch Logs to see what happened. Express is at-least-once for the async kind, so a run can happen more than once. The sync kind is at-most-once and returns the result to the caller. Because of this, Express suits steps that are safe to repeat, like writing a record to Amazon DynamoDB. Standard is exactly-once and suits steps that must not repeat, like taking a payment.

Reach for it when

  • High volume event processing, like IoT or streaming data, where each run finishes in seconds
  • Short data transform steps that are safe to run twice
  • A small chain of steps behind an API call, using the sync mode, so the caller gets the answer back
  • Cutting Step Functions cost when you run millions of short workflows

Do not reach for it when

  • Do not use it for work that takes more than five minutes. Use a Standard workflow.
  • Do not use it for anything that must run exactly once, like charging a card. Use a Standard workflow.
  • Do not use it if you need human approval steps or long waits. Express does not support the callback or job-run patterns.
  • Do not use it if you need Distributed Map or Activities. Those are Standard only.
  • Do not go looking for it as a product to sign up for. You get it by choosing the type when you make a Step Functions state machine.

One small example

A sensor sends readings every second. An Express workflow cleans each reading, checks it against a rule, and writes it to DynamoDB. Millions run a day and each takes under a second.

How you pay

You pay per run, plus the run time and the memory it used. There is no charge per step, unlike Standard workflows. Logs sent to CloudWatch cost extra. Check the Step Functions pricing page for current rates.
