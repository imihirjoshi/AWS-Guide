Amazon DataZone

Analytics  ·  Advanced, most people never need it

A catalogue where staff can find the company's data and ask for permission to use it.

Picture it as

A staff intranet directory. You search for what you need, see who owns it, and click a button to request access.

What it actually does

It gives each team a project space, publishes datasets with business descriptions, and runs a request and approval flow for access, with Lake Formation doing the actual enforcement. AWS has folded it into Amazon SageMaker Unified Studio, so newer accounts often meet it under that name rather than as DataZone. It solves an organisational problem, not a technical one, so it only pays off in a company with many teams and real governance rules.

Reach for it when

  • A large company where people cannot find what data exists
  • Formal approval trails are needed for data access
  • Standardising business definitions across departments

Do not reach for it when

  • Under a few teams, a shared document and Lake Formation grants do the job
  • For the technical table metadata itself, that is the AWS Glue Data Catalog underneath
  • For enforcing permissions, that is Lake Formation, DataZone just requests them

One small example

An analyst searches the portal for customer churn, finds the owning team, requests access and gets it approved in a day.

How you pay

Per active user per month plus metadata storage and API calls. The user count is the part that grows unnoticed as people are added and never removed.
