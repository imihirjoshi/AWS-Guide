AWS Cloud Control API

Developer Tools  ·  Advanced, most people never need it

One set of five commands to create, read, update, delete and list almost any AWS thing.

Picture it as

A universal remote. Instead of a different remote for the TV, the fan and the lights, one remote with the same five buttons works on all of them.

What it actually does

Normally every AWS service has its own API with its own command names. Cloud Control API puts a single CRUDL interface in front of hundreds of resource types, so tool builders write one piece of code instead of hundreds. It is mostly used by people building infrastructure tools, like the Terraform Cloud Control provider. Coverage is not total, and it can lag behind a service's own API by a while.

Reach for it when

  • You are building a tool that manages many AWS resource types
  • You want new resource support without writing per service code
  • You already use CloudFormation resource types and want them callable directly

Do not reach for it when

  • You just want to create a few resources, use the AWS CLI or CDK
  • You need a service feature that is new or unusual, call that service's own API

One small example

A small internal tool that can create an S3 bucket, a DynamoDB table or an SNS topic using the same function, just with a different type name.

How you pay

No charge for the API itself. You pay for whatever resources it creates, and those bills are easy to forget because the tool hides which service it touched.
