AWS Security Hub

Security and Identity  ·  Common, learn when you need it

One screen that gathers security problems from all your AWS security tools.

Picture it as

A hospital nurses' station where every ward's alarms come to one desk, instead of ringing in rooms nobody is standing in.

What it actually does

Careful, the name moved. In 2025 the original service was renamed Security Hub CSPM, which runs best-practice checks against standards like CIS and AWS Foundational Security Best Practices. A newer service took the plain name Security Hub and focuses on correlating findings into prioritised exposures using the OCSF format. Both pull in findings from GuardDuty, Inspector, Macie and partners. Older blog posts and docs saying just Security Hub usually mean the CSPM one.

Reach for it when

  • More than one AWS security service switched on and too many alerts
  • You need a compliance score against CIS or PCI controls
  • Sending security findings to a ticketing system or SIEM

Do not reach for it when

  • It does not detect threats itself, GuardDuty and Inspector do that
  • It does not fix anything, you still need automation or people
  • With one tiny account and no compliance need, the check charges may not be worth it

One small example

GuardDuty, Inspector and Macie findings for twelve accounts land in one place, and a critical one opens a Jira ticket automatically.

How you pay

Per security check run and per finding ingested. Turning on every standard across many accounts multiplies the check count quickly.
