AWS Lake Formation

Analytics  ·  Advanced, most people never need it

Decides who is allowed to see which tables, columns and rows of your data in S3.

Picture it as

A library where some shelves are open to everyone, some need a staff pass, and a few books have certain pages taped over.

What it actually does

It sits on top of the AWS Glue Data Catalog and lets you grant permissions in database terms, this team may read this table but not the salary column, instead of writing S3 bucket policies. Athena, Redshift Spectrum, EMR and Glue then honour those grants. It is genuinely fiddly, it layers on top of IAM rather than replacing it, and mixing the two is the usual source of confusion and denied queries.

Reach for it when

  • Many teams share one data lake and need different access
  • You must restrict specific columns or rows, such as hiding personal data
  • Sharing catalogued tables with another AWS account

Do not reach for it when

  • One team, one bucket, use plain IAM and S3 policies, this is overkill
  • For a business-facing catalogue people browse and request access through, use Amazon DataZone
  • If your data lives in a database rather than S3, use that database's own permissions

One small example

Analysts can query the orders table but the card number column comes back blank for everyone outside the payments team.

How you pay

The service itself is largely free. You pay for the query engines and storage underneath, and for the extra compute when it filters rows and columns for you.
