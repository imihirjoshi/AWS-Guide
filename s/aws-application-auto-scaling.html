AWS Application Auto Scaling

Management and Governance  ·  Common, learn when you need it

Adds and removes capacity automatically for AWS services other than plain servers.

Picture it as

A cafe that opens extra tills when the queue gets long and closes them when it is quiet.

What it actually does

It watches a metric, like CPU or queue length, and changes how much capacity a service has. It covers things like ECS tasks, DynamoDB tables, Aurora read replicas and SageMaker endpoints. It does not scale EC2 instances, that is EC2 Auto Scaling, and the similar names cause real confusion.

Reach for it when

  • Scaling the number of ECS or Fargate tasks
  • Scaling DynamoDB read and write capacity
  • Scaling a machine learning endpoint by traffic

Do not reach for it when

  • Scaling EC2 virtual machines, use EC2 Auto Scaling groups
  • Traffic that spikes in seconds, scaling takes minutes, so use a queue or serverless like AWS Lambda

One small example

Your order service runs 3 containers overnight and 30 at lunchtime, with nobody touching it.

How you pay

The scaling itself is free. You pay for whatever capacity it turns on, which is the whole point and also the bill.
