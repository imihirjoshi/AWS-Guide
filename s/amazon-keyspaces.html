Basics / Services / Databases

Amazon Keyspaces

Databases  ·  Advanced, most people never need it

It stores data the way Apache Cassandra does, without you running any Cassandra servers.

Picture it as

Renting a self-drive car that has the same controls you already learned, so you can drive off without lessons.

What it actually does

It accepts Cassandra CQL queries and drivers, and scales storage and throughput on its own. It is API compatible, not real Cassandra, so some features such as materialized views and certain consistency options behave differently or are missing. It is a narrow service, mainly useful if you already have Cassandra code.

Reach for it when

  • You have a Cassandra application and do not want to operate a cluster
  • You need wide-row, high-write workloads with a known access pattern
  • Your team already knows CQL

Do not reach for it when

  • You are starting a new project on AWS with no Cassandra history, DynamoDB is the better default
  • You depend on Cassandra internals or unusual features, run Cassandra yourself on EC2

One small example

A telecom team lifts an existing CQL-based event store off a self-managed cluster and keeps the same client code.

How you pay

Per read and write request plus storage, or provisioned capacity. Costs climb fast with large rows, because you are billed by data size per operation, not per row.
