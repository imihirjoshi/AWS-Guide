AWS IoT Events

Internet of Things  ·  Advanced, most people never need it

A service, now being retired, that watched device readings and reacted when a pattern appeared.

Picture it as

A checklist on the wall that says: if the light stays red for ten minutes, ring the bell. It is being taken down.

What it actually does

IoT Events let you define a state machine in the console, for example normal, warning and fault, with the conditions that move a device between states and the actions to take, such as sending an SNS message. It is being retired. New customers were cut off on 20 May 2025 and support ends on 20 May 2026. AWS suggests rebuilding the logic with IoT Core, Lambda, DynamoDB for state, and EventBridge.

Reach for it when

  • Nothing new, it is closing
  • Only if you already run it and are planning the move off it

Do not reach for it when

  • Any new alerting logic, use IoT Core rules into Lambda with state in DynamoDB
  • Simple threshold alarms, a CloudWatch alarm is enough
  • Complex workflow across steps, use Step Functions

One small example

A rule that raised a ticket if a freezer stayed above minus fifteen degrees for twenty minutes now runs as a Lambda with state kept in DynamoDB.

How you pay

Charged per message evaluated and per detector. Becomes irrelevant after May 2026.
