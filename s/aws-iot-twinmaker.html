AWS IoT TwinMaker

Internet of Things  ·  Advanced, most people never need it

Builds a live 3D model of a real factory or building that updates from its sensors.

Picture it as

A doll's house of your factory where the tiny lights turn on when the real lights turn on.

What it actually does

It takes a 3D model you already have, then wires each part of it to live data from sensors, cameras and business systems. Operators see the building on screen with real readings attached. The honest limitation is that it does not create the 3D model or the sensors for you, and the viewing layer is a Grafana plugin, so you need both before it is useful.

Reach for it when

  • Plant operators need one screen showing equipment status in physical context
  • You already have CAD or 3D models of a site and live sensor data
  • Diagnosing which machine on a line is causing a problem

Do not reach for it when

  • If you only need charts and alarms, use Amazon CloudWatch or Amazon Managed Grafana. A 3D scene is a lot of work for a line graph.
  • If you just need to collect and store sensor readings, use AWS IoT Core and a database.
  • Most companies never need this. It suits large industrial sites with existing 3D models.

One small example

A cookie factory shows its oven in 3D, and the oven turns red on screen when its real temperature sensor goes out of range.

How you pay

You pay per query against the digital twin and per GB of data stored, plus the cost of every underlying service. The surprise is that the bill is mostly the other services, the sensors, storage and the Grafana users, not TwinMaker itself.
