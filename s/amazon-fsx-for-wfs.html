Amazon FSx for WFS

Storage  ·  Common, learn when you need it

A Windows file share, the kind with drive letters, run by AWS.

Picture it as

The shared drive at work that everyone calls the P drive, except nobody has to look after the server.

What it actually does

It gives you SMB shares with real Windows behaviour, NTFS permissions, Active Directory integration, shadow copies for user self-restore, and DFS namespaces. It is the natural home for Windows workloads and for file shares users map from their laptops. It is Windows-protocol first, Linux clients can mount SMB but it is not the smooth path, and it needs an AD directory, either your own or AWS Managed Microsoft AD.

Reach for it when

  • Moving an on-premises Windows file server to AWS
  • SharePoint, SQL Server or .NET apps wanting an SMB share
  • User home directories and department shares

Do not reach for it when

  • For Linux workloads, use EFS or FSx for OpenZFS
  • If you have no Active Directory and do not want one, this is heavy going
  • For app data accessed by key, S3 costs much less

One small example

A 300-person firm retires its old file server and maps P: to an FSx for Windows share joined to their existing Active Directory.

How you pay

Per GB provisioned, SSD or cheaper HDD, plus provisioned throughput capacity per MBps and backup storage. The surprise is the separate throughput charge and the fact that HDD has a minimum size.
