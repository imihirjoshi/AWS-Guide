Amazon Managed Workflows for Apache Airflow

Application Integration  ·  Advanced, most people never need it

It runs Apache Airflow for you, so scheduled data pipelines have somewhere to live.

Picture it as

Hiring a caretaker for a machine you already own. Same machine, same controls, you just stop doing the maintenance.

What it actually does

Airflow is the common open source tool for scheduling data jobs written as Python DAGs. MWAA runs the scheduler, workers and web UI inside your VPC and handles version upgrades. It is still Airflow, so the quirks, the Python dependency conflicts and the learning curve all come with it.

Reach for it when

  • Your team already writes Airflow DAGs
  • Daily data pipelines with dependencies between many steps
  • You want to stay portable rather than tied to an AWS-only workflow tool

Do not reach for it when

  • A handful of scheduled tasks, use EventBridge Scheduler with Lambda
  • Event-driven application logic rather than batch data jobs, use Step Functions

One small example

A data team runs a nightly DAG that pulls from three databases, transforms in Glue, and loads into Redshift.

How you pay

Per environment-hour for the scheduler and web server, plus workers and storage. The surprise is the base cost, roughly 350 dollars a month for a small environment even if no DAG ever runs.
