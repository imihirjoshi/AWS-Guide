Amazon Security Lake

Security and Identity  ·  Advanced, most people never need it

It puts all your security logs in one place, in one standard format.

Picture it as

Everyone in the company finally agreeing to write dates the same way, so the records can actually be read together.

What it actually does

Security Lake collects CloudTrail, VPC Flow Logs, Route 53 logs, findings and third-party sources into your own S3 bucket, converted to the OCSF standard schema and stored as Parquet. The value is the normalisation, since you can then query everything with Athena or feed one clean feed to Splunk or OpenSearch. It is plumbing. It shows you no dashboards and raises no alerts by itself.

Reach for it when

  • Many accounts and several log sources you cannot join today
  • Feeding a SIEM without building a converter per source
  • Keeping years of security logs cheaply for investigations

Do not reach for it when

  • Not a detection tool, use GuardDuty and Security Hub for that
  • Not worth it for one or two accounts, just query CloudTrail with Athena
  • If your SIEM already ingests everything happily, this adds a layer for nothing

One small example

A responder runs one Athena query across three years of flow logs and CloudTrail from forty accounts, without joining formats by hand.

How you pay

Per gigabyte of data converted and ingested, plus the ongoing S3 storage and Athena query costs you would pay anyway. Flow logs are usually the biggest volume.
