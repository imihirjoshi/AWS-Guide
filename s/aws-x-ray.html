AWS X Ray

Developer Tools  ·  Common, learn when you need it

Follows one request through all your services and shows where the time went.

Picture it as

A parcel tracking page. You see every depot the parcel passed through and how long it sat at each one.

What it actually does

X-Ray collects traces from instrumented applications and draws a service map plus a timeline of each request. You must instrument your code or run an agent, it does not appear on its own. It samples by default, so a rare slow request may never be recorded. AWS now points new work toward OpenTelemetry and CloudWatch Application Signals, with X-Ray as the storage behind them.

Reach for it when

  • A request is slow and you do not know which service caused it
  • You have several services calling each other and need a map
  • You want to see downstream AWS call latency per request

Do not reach for it when

  • You have one small service, logs and CloudWatch metrics are enough
  • You already run Datadog, Honeycomb or another tracing tool, do not double instrument

One small example

Finding that a 3 second API response was actually 2.6 seconds spent on one DynamoDB query, not on your code.

How you pay

Per trace recorded, per trace retrieved and per trace scanned. Turning sampling up to 100 percent on a busy service is the bill shock.
