AWS Transform

Migration and Transfer  ·  Advanced, most people never need it

An AI agent that reads your old applications and rewrites them for AWS.

Picture it as

A translator who reads an old handwritten ledger and types out a modern version, then you still have to check every page.

What it actually does

An agentic AI service for large modernisation jobs, covering mainframe COBOL to Java, .NET Framework to modern .NET, and VMware workloads to EC2. It assesses the code, writes documentation, converts it and helps test. It is new, aimed at big enterprise programmes, and the output still needs human review, so treat it as a fast first draft rather than a finished migration.

Reach for it when

  • Thousands of files of legacy code that nobody understands any more
  • Upgrading old .NET Framework applications at scale
  • You need a documented assessment before committing to a migration

Do not reach for it when

  • A handful of applications, a developer with Amazon Q or Claude will be quicker and cheaper
  • You expect a working system with no review, the converted code must be tested against the old system's output

One small example

A team points it at a .NET Framework application and gets a ported .NET 8 version plus a list of the parts it could not convert.

How you pay

Varies by workload type and has been offered free for some transformation paths. The real cost is the engineering time spent checking what it produced.
